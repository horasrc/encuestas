Instalar el módulo de Encuestas en el portal

Guía paso a paso · Detalle completo en INTEGRACION.md dentro del zip

Antes de empezar

  • Proyecto del portal abierto en Visual Studio
  • SQL Server Management Studio conectado a la base del portal

1 Copiar el módulo al proyecto

  • Descomprimir el zip en cualquier carpeta.
  • Copiar Encuestas\Encuestas.Web\Areas\Encuestas al proyecto del portal, para que quede Portal\Areas\Encuestas\.
  • Visual Studio: Explorador de soluciones → Mostrar todos los archivos → clic derecho en Areas\Encuestas → Incluir en el proyecto.

2 Revisar versiones

  • Newtonsoft.Json en 13.x (Herramientas → Administrador de paquetes NuGet). Si es menor, actualizarlo.
  • MVC: comparar las versiones de System.Web.Mvc y System.Web.WebPages.Razor en Views\Web.config del portal con las de Areas\Encuestas\Views\Web.config (viene con 5.2.3). Si son distintas, poner las del portal.

3 Configurar el Web.config del portal

Dentro de <appSettings>:

<add key="Surveys:UseMockData" value="false" />
<add key="Surveys:Repository" value="Sql" />
<add key="Surveys:CatalogProvider" value="Sql" />
<add key="Surveys:ConnectionStringName" value="NombreDeLaCadenaDelPortal" />
<add key="Surveys:Layout" value="~/Views/Shared/_Layout.cshtml" />
  • ConnectionStringName: el name de la cadena que ya existe en <connectionStrings>.
  • Layout: el layout del portal debe tener @RenderSection("scripts", required: false) antes de </body>.

3b Seguridad: la pone el portal

El módulo no restringe a nadie. El portal decide quién entra a cada ruta:

Administrar (solo administradores)Responder (colaboradores)
/Encuestas, /Encuestas/Constructor/{id} y /Encuestas/Api/ List, Survey, History, Catalogs, Results, Create, Duplicate, Delete, SaveDraft, Publish, CreateVersion, ChangeStatus /Encuestas/Responder/{id} y /Encuestas/Api/ Published, Eligibility, Submit, LastResponse
  • Aplicar la regla del portal (ejemplo de filtro listo en INTEGRACION.md, paso 3). Al bloquear, responder 403, no redirigir.
  • Si el portal no usa User.Identity.Name, indicar el usuario en Global.asax.cs:
ModuloEncuestas.Infrastructure.SurveyUser.Resolver =
    http => http.Session == null ? null : (string)http.Session["Usuario"];

4 Crear las tablas (SSMS, base del portal)

  • Seleccionar la base del portal en la barra de herramientas.
  • Abrir y ejecutar (F5) Database\schema.sql. Debe terminar con Esquema enc: 12 tablas del módulo.
  • Si sale «Cannot find the user 'dbo'» (no se permite crear el esquema enc): usar los scripts de Database\esquema-IC\ y poner en el Web.config <add key="Surveys:Schema" value="IC" /> (detalle en INTEGRACION.md, paso 4).
  • Abrir y ejecutar (F5) Database\org-schema.sql.
  • Dar permisos a la cuenta del sitio:
GRANT SELECT, INSERT, UPDATE, DELETE ON SCHEMA::enc TO [TUDOMINIO\cuenta-del-sitio];
No ejecutar seed.sql ni org-seed.sql (son datos de ejemplo). Los scripts solo crean el esquema enc; no tocan tablas del portal.

5 Enlace en el menú del portal

<a href="@Url.Action("Index", "Encuestas", new { area = "Encuestas" })">Encuestas</a>

6 Compilar y probar

  • Usuario administrador abre /Encuestas → aparece el listado.
  • Crear una encuesta, Publicar, abrir /Encuestas/Responder/{id} y responder.
  • Usuario no administrador: el portal le bloquea /Encuestas, pero la página para responder sí abre.
  • En SQL: SELECT * FROM enc.SurveyAuditLog muestra quién hizo cada acción (si dice sistema, revisar SurveyUser.Resolver).

7 Publicar

  • Publicar el portal como siempre.
  • En IIS: Autenticación de Windows activada y autenticación anónima desactivada.

Si algo falla

MensajeSolución
"La sección scripts se definió pero no se representó"Agregar @RenderSection("scripts", required: false) al layout del portal.
Error de versión de System.Web.MvcPaso 2: igualar versiones en Areas\Encuestas\Views\Web.config.
No conecta a la baseRevisar que Surveys:ConnectionStringName sea igual al nombre de la cadena del portal.
"La página expiró por seguridad" al guardarDesactivar la autenticación anónima en IIS.
403 con un usuario que debería administrarRevisar la regla de seguridad del portal (paso 3b).
"Debes iniciar sesión para responder", o la bitácora dice sistemaEl módulo no recibe el usuario: configurar SurveyUser.Resolver (paso 3b).

Después: conectar empleados y sucursales

Mientras las tablas enc.Org* estén vacías, el módulo funciona pero la segmentación solo permite "Todos los colaboradores". Para usar los datos del portal: llenar los TODO de Database\org-vistas-plantilla.sql con los nombres de las tablas de empleados y sucursales y ejecutarlo en SSMS.
